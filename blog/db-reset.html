The day db reset wiped my accounts

Two outages in one week on THE SMART’s local stack. Both self-inflicted, both now written into the project’s rules.

22 September: db reset

I had a new migration to apply, and I ran supabase db reset. It does apply migrations — by rebuilding the local database from scratch. Every account I’d signed up with, every point, every streak, all the progress: gone.

Nothing was lost in production. But that was luck, not process. The rule now sits in the README, in bold:

npx supabase db dump --local --data-only -f backup.sql   # keep it outside the repo
npx supabase migration up
npm run types:gen

Back up, then apply only what’s new. db reset is for empty stacks.

Same week: the AI went silent

All four AI features stopped at once, and 14 security tests failed with them. The code was fine. Docker had crashed when the disk filled up, and when it came back, every container restarted — except supabase_edge_runtime_mybac, the one that runs the AI function. It sat at Exited (255).

Worse: npx supabase start reported that it had handled it. It hadn’t. A plain docker start supabase_edge_runtime_mybac did. The tutor answered in 2.7 seconds, and the security suite went back to green.

Why it took longer than it should have

Every failure inside the function collapsed into the same generic 500: an invalid key, a missing key, an unreachable server, malformed JSON — all identical from the client. The real cause only showed in the server logs. And old logs stay visible even when the container is dead, so without --since you can spend an afternoon diagnosing yesterday’s error.

The checklist I wrote afterwards

  1. The container first, always. docker ps -a | grep edge — if it says Exited, that’s your answer and everything else is a waste of time.
  2. Fresh logs only. docker logs supabase_edge_runtime_mybac --since 5m.
  3. Is the key there? supabase/functions/.env → GEMINI_API_KEY. A missing key looks like any other 500.
  4. Is Gemini reachable? curl -sI https://generativelanguage.googleapis.com/ — a quick answer means the network is fine and the problem is elsewhere.
  5. One real end-to-end call as a premium user. Healthy is a 200 in about 3 seconds.

And the root cause that keeps coming back: a full disk.

Takeaway

Write the incident into the repo the same day. A rule in DEVELOPMENT.md beats a memory of a bad afternoon — and it’s the only kind of memory the next developer, or the next AI assistant, will actually read.
